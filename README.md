# SELVEDGE

## 1. What SELVEDGE is attempting

Buy useful neural computation with **bytes, not FLOPs**. The active budget is a
hard ceiling of **1,000,000,000 unique learned parameters per output token**;
the substrate behind it may be as large as storage allows (NVMe, host RAM,
VRAM). The scientific question is stated so that it can fail:

> Does a *learned*, causally available, physically costed selection and execution
> path put the quality / active-parameter / bytes-per-token / latency frontier
> beyond what post-hoc sparse inference and offloading already achieve?

Three claims are kept apart and are never merged into one number: a **neural
architecture** claim (a mechanism beats matched controls on verified tasks), a
**local inference** claim (the assembled system beats a quantised local baseline
at equal residency), and a **system capability** claim (the system finishes work
of a declared class offline). Every comparison carries active unique parameters,
accessible capacity, bytes moved and cold bytes separately
(`docs/PROGRAM-PLAN.md` P7.7).

The plan is tiered: ACTIVE work is the running T2 pilot and the single next
decisive test; CANDIDATE work has a cheap decisive experiment and a kill
criterion; HYPOTHESIS work is retained with no implementation commitment. The
tier index and the legend are in `docs/PROGRAM-PLAN.md` §0.1.

## 2. What has actually been measured

**Two negative results, both reproducible.**

- **Static whole-group omission is a cliff** (`results/M1-FRONTIER.md`).
  Uniform, magnitude, frequency, whole-layer and greedy allocations were measured
  on a pinned, hash-split held-out set with paired bootstrap CIs. Every arm at or
  below the ceiling is far outside the registered acceptable and usable tiers.
  Two complete runs produced bitwise-identical aggregates, and the failed
  attempts are retained.
- **Per-token post-hoc selection does not escape it** (`results/M2-SELECTORS.md`,
  `docs/M2-CORRECTION.md`). Activation magnitude at matched realized parameters
  beats the best static arm, and every other causally available per-token arm is
  worse than magnitude. Even a causally *unavailable* per-token oracle at the
  compliant budget is outside the usable tier. The selectors that score best read
  all gate/up channels, so they are not physically compliant. The inference-only
  branch is closed for this teacher at this granularity.

**Infrastructure that exists and is measured** (each with receipts; see
`results/REPORT.md` for the list and `docs/` for the method):

- a hash-pinned teacher oracle that runs offline after one documented fetch
  (`docs/MODELS.md`, `docs/TRAINING.md`);
- exact accounting and bit-exact shard reconstruction on the real Qwen3-0.6B and
  Qwen3-1.7B checkpoints (`docs/ARCHITECTURE.md`, `docs/SHARD-FORMAT.md`);
- measured host-RAM/NVMe baselines with three-repeat variance (`docs/STORAGE.md`);
- a trace-driven execution simulator calibrated from those measurements and
  validated on held-out arms (`docs/SIMULATOR.md`);
- a real CPU inference runtime with a per-token witness and accounting row
  (`docs/RUNTIME.md`);
- a capability court: a fresh Rust suite, a bounded checker sandbox, paired
  category-stratified CIs, a ten-field control matrix, a pre-registration bound
  to the suite hash, and anti-gaming checks that are tested
  (`docs/CAPABILITY-COURT.md`).

**The trained branch (T2) is decided, and the negative is not the product.** Five
arms — dense adapter `D`, hashed memory `M`, routed specialists `X`, naive hybrid
`H`, error-directed hybrid `H*` — trained from one frozen Qwen3-0.6B core at one
budget and one seed, and were evaluated on the registered next-token instrument
(KL/NLL/top-1 against the teacher) and then on the verified-task suite. The
registered rule fired against error-directed routing (K15/K16), and against `X`
(K18) because its positive primary-composite gain came with a pooled-KL
regression that the registered no-regression margin forbids. **What `X` measured
is the trade the program now has to settle**, and that question is registered as
its own pre-registration (`docs/EXPERIMENT-CONTRACT.md` T4, the K18 trade
question) rather than re-thresholded, with the two numbers printed there from the
verdict receipt. Status is generated below, from the receipts, not typed.

## 4. What still blocks a frontier claim

1. **A capability measurement that can rank arms.** All five arms were scored on
   the verified-task suite and every one floored at zero, so the comparison is
   uninformative rather than negative (`docs/CAPABILITY-COURT.md` §12). The
   registered response is a dated endpoint amendment: a 10%-relative claim needs a
   six-figure item count *per category* at the measured baseline, which no feasible
   suite reaches, so the primary endpoint becomes an absolute effect with a
   pre-registered minimum, with candidate-ranking accuracy registered as the
   discrimination endpoint and never pooled with it (§7.3 of the same document).
2. **A stage that wins.** No capability win exists and no frontier advantage
   exists. The frontier program's six stages each carry a named win condition and
   a concrete next route if they miss; a miss is a route change, not a verdict on
   the mechanism.
3. **The pre-scaling blockers** (`docs/PROGRAM-PLAN.md` P12.15): the routed-overflow
   mask defect is measured and has a registered sensitivity (`docs/P12.1-DISPATCH-AUDIT.md`),
   and the `H*` target/deployment mismatch is measured and registered as P12.17.
   Neither is repaired by a claim; each is repaired by its successor run.
4. **The control matrix rows and the thresholds** must exist before the
   experiments they govern — the ordering inversion corrected in
   `docs/PROGRAM-PLAN.md` §0.2.
5. **Runtime corrections** (P14.1–P14.3): the exact path still re-decodes every
   cached shard to `f32` on each read (every shard the token reads: 28 layers ×
   48 groups = 1,344 reads, arithmetic), prefetch is synchronous, and prefill is
   token-at-a-time. Latency and
   cold-byte claims are not comparable across systems until these land.
6. **Evaluation scale and separation** (P14.4–P14.7): the suite's calibrated
   formats are not yet accepted (`docs/CAPABILITY-COURT.md` §17.5), correctness
   must be reported separately from reference-continuation likelihood, and an
   external comparison needs a sealed set.

What is deliberately *not* claimed anywhere: a **competitive** performance claim
(a Pareto win over any external system), a **GPU** performance claim, a
capability number, or a trained-model advantage. This is not a claim that nothing
was measured: the CPU runtime has **measured latency, throughput and
byte-traffic receipts** (`results/runtime/court-e-*`, summarised in
`docs/PERF-NUMBERS.md` and `docs/RUNTIME.md`). Those are measurements of *this*
implementation on *this* host, and they are reported as such — not as a
comparison against any external system. See `docs/LIMITATIONS.md`.

## Rules this repository enforces mechanically

- **No host builds or tests.** Everything runs in an OOM-protected Docker court
  (`scripts/docker-court.sh`) with a hard memory limit, swap limited to the same
  value, a pids limit, a CPU limit and a bounded `/tmp`. Missing limits refuse to
  run; there is no host fallback.
- **No fabricated evidence.** Every court run writes a JSON receipt under
  `results/courts/` containing the command, image reference and image id, the
  applied limits (verified by inspecting the live container), network mode,
  exit code, duration and toolchain versions.
- **No hand-written status.** The current-status blocks in `README.md` and
  `results/REPORT.md` are generated from `results/t2/pilot-state.json`, the
  verdict receipt and the capability comparison by
  `scripts/status_consistency.py`. The `status_consistency` court re-derives them
  and fails closed on a stale block *or* on a sentence in either document that
  contradicts a receipt (a run said to be training when every arm is evaluated, a
  verdict said not to exist when one does). Tested by
  `scripts/courts/status_consistency_negative_cases.sh`.
- **No hand-written published numbers.** Numbers in tracked documentation live
  between `BEGIN GENERATED` / `END GENERATED` sentinels produced by
  `scripts/perf_numbers.py` from `docs/perf-numbers.json`. See
  `docs/PERF-NUMBERS.md`.
- **Operator commit identity only.** `scripts/check-commit-identity.sh` fails
  closed unless the repository-local identity is the operator's and every scanned
  commit carries it.

## Court interface for later work

- **Rust builds and tests:** `scripts/court rust test`, `... build`, `... fmt --all
  --check`, `... clippy --workspace --all-targets -- -D warnings`, or
  `scripts/docker-court.sh rust -- cargo <args>`. The container runs as the
  host user with `CARGO_HOME=/cargo` (persistent registry/git cache) and
  `CARGO_TARGET_DIR=/work/target` (persistent target dir). Network is disabled,
  and `CARGO_NET_OFFLINE=true` is set, so dependency resolution fails loudly
  instead of hanging. Fetch dependencies with an explicit networked run:
  `scripts/court --net rust -- cargo fetch` and commit `Cargo.lock`.
- **Python oracle jobs:** `scripts/court oracle -- python3 oracle/<job>.py`.
  The oracle image pins torch, transformers, tokenizers, safetensors and numpy;
  it mounts `~/.cache/selvedge/hf` read-write at `/hf-cache` and is offline
  unless `--net` is passed. `trust_remote_code` is never enabled. The plain
  `python` court remains the lightweight court for `perf_numbers` and helper
  scripts.
- **I/O courts:** `scripts/court io -- <argv>` uses the Python court image
  (`fio`, `dd`, `df`) with the same limits.
- **GPU:** add `--gpu`. On this host that resolves to explicit device
  passthrough because `--gpus all` fails without a CDI specification; the
  receipt records which mode was used and why. A GPU court fails closed rather
  than falling back to CPU.
- **Limits:** `SELVEDGE_MEM` (default `8g`), `SELVEDGE_CPUS` (`8`),
  `SELVEDGE_PIDS` (`1024`), `SELVEDGE_TMP` (`2g`), `SELVEDGE_NOFILE` (`65536`).
  Empty, zero or malformed values refuse to run.
